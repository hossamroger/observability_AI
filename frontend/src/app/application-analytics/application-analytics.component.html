How these trends are calculated

One on-demand query for all supported metrics and platforms. Each point represents its own time bucket, not a rolling snapshot. Sessions can occur in more than one bucket; do not sum them as unique sessions. Startup percentiles use eligible session starts and matched screen events; the final 5 minutes cannot complete the required follow-up. Missing buckets are not filled with zero.

How stored trends are calculated

Each point is a separately collected rolling-window snapshot. Counts overlap and must not be summed; percentiles are not averaged. Missing intervals are not interpolated. The new default local database persists across restarts; previous in-memory observations cannot be recovered.
